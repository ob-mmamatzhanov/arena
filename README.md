# arena

Авторитетный сервер для real-time 2D-шутера с видом сверху, написанный на Go. Клиенты подключаются по WebSocket, шлют свой ввод, а сервер симулирует мир с частотой 20 тиков в секунду и каждый тик рассылает всем снапшот состояния.

- одна комната `lobby` до 8 игроков;
- движение с препятствиями, стрельба с перегревом ствола, рывок (dash);
- пикапы здоровья и ускорения;
- раунды с лимитом времени и фрагов и перерывом между ними;
- события тика (попадания, убийства, выстрелы) для эффектов на клиенте;
- детерминированная симуляция без аллокаций в горячем цикле.

## Быстрый старт

Нужен Go 1.27+.

```sh
go run ./cmd/server -addr :8080 -origins localhost:5173
```

| Флаг       | По умолчанию | Описание                                                                   |
|------------|--------------|----------------------------------------------------------------------------|
| `-addr`    | `:8080`      | адрес HTTP-сервера                                                         |
| `-origins` | пусто        | разрешённые `Origin` для WebSocket через запятую, например `localhost:5173` |

Эндпоинты:

- `GET /ws` — WebSocket-подключение игрока;
- `GET /healthz` — `200 ok`, пока комната работает, иначе `503`.

Сервер корректно завершается по `SIGINT`/`SIGTERM`: сначала закрывает WebSocket-соединения, затем останавливает HTTP-сервер.

## Игровые механики

Значения по умолчанию заданы в `game.DefaultConfig()`.

| Механика    | Параметры                                                                                          |
|-------------|----------------------------------------------------------------------------------------------------|
| Мир         | 1000×1000, 6 прямоугольных препятствий                                                             |
| Игрок       | скорость 200 ед/с, радиус 12, 100 HP                                                               |
| Смерть      | 3 с мёртв (не цель, не двигается, ввод игнорируется), затем респаун в свободной точке не ближе 150 к убийце |
| Неуязвимость | 1 с после входа, респауна и начала раунда: урона нет, пули гаснут о игрока, стрелять можно          |
| Стрельба    | пуля 500 ед/с, живёт 1,5 с, урон 25, кулдаун 0,2 с; пули гаснут о стены и границы мира             |
| Перегрев    | каждый выстрел +0,2 heat, остывание 0,5/с; разброс до ±0,25 рад при heat = 1; первый выстрел точен |
| Рывок       | импульс 700 ед/с на 150 мс, кулдаун 3 с                                                             |
| Патроны     | 12 при появлении, респауне и новом раунде, максимум 30; без патронов выстрел невозможен             |
| Пикапы      | раз в 20 с, не больше 3 на карте, тип взвешенно: `ammo` 50 % (+10 патронов), `health` 30 % (+50 HP), `speed` 20 % (×1,6 к скорости на 5 с) |
| Раунды      | 120 с или до 10 фрагов, затем перерыв 8 с, во время которого мир заморожен                         |

## Протокол

Все сообщения передаются как JSON в текстовых кадрах WebSocket. Полное описание типов находится в [`internal/net/protocol.go`](internal/net/protocol.go).

### Клиент → сервер: `Input`

Клиент шлёт ввод каждый свой кадр, даже без изменений: это заодно heartbeat. Если от клиента ничего не приходит 10 секунд, соединение закрывается.

```json
{ "seq": 42, "moveX": 0.7, "moveY": -0.7, "angle": 1.57, "fire": true, "dash": false }
```

- `seq` — монотонный номер ввода; сервер возвращает последний применённый в `lastSeq`, это нужно для client-side prediction и reconciliation;
- `moveX`, `moveY` — направление движения, вектор длиннее 1 нормализуется;
- `angle` — направление взгляда в радианах;
- `fire` — огонь зажат, `dash` — запросить рывок.

Если за тик пришло несколько вводов, применяется самый свежий по `seq`, а флаги `fire` и `dash` объединяются по ИЛИ, чтобы короткие нажатия не терялись.

### Сервер → клиент: `welcome`

Приходит один раз сразу после подключения. Содержит статические данные, нужные клиенту для отрисовки и предсказания движения:

```json
{
  "type": "welcome", "playerId": 3, "room": "lobby", "tickRate": 20,
  "width": 1000, "height": 1000, "speed": 200, "radius": 12,
  "obstacles": [{ "x": 440, "y": 440, "w": 120, "h": 120 }]
}
```

Если комната заполнена, соединение закрывается с кодом `1013 Try Again Later`.

### Сервер → клиент: `snapshot`

Рассылается каждый тик:

```json
{
  "type": "snapshot", "tick": 1234,
  "players": [{ "id": 3, "x": 512, "y": 300, "angle": 1.57, "heat": 0.4, "hp": 75,
                "score": 2, "ammo": 9, "boosted": false, "dashCd": 1.2, "lastSeq": 42,
                "dead": false, "respawnIn": 0, "invuln": false }],
  "bullets": [{ "id": 17, "owner": 3, "x": 520, "y": 330, "vx": 0, "vy": 500 }],
  "pickups": [{ "id": 5, "type": "health", "x": 200, "y": 700 }],
  "events":  [{ "type": "hit", "x": 520, "y": 410, "targetId": 4, "shooterId": 3 }],
  "round":   { "phase": "play", "timeLeft": 87.5 }
}
```

Скорость пуль передаётся, чтобы клиент мог экстраполировать их между снапшотами. Поле `events` есть только в тиках, где что-то произошло, и каждое событие приходит ровно в одном снапшоте:

| Событие     | Поля                                  |
|-------------|---------------------------------------|
| `hit`       | `x`, `y`, `targetId`, `shooterId`     |
| `kill`      | `targetId`, `shooterId`               |
| `shot`      | `playerId`, `x`, `y`                  |
| `bulletHit` | `x`, `y` — пуля ударилась о стену, границу или неуязвимого игрока |
| `pickup`    | `playerId`, `pickupType`              |
| `respawn`   | `playerId`, `x`, `y`                  |

Во время перерыва `round` выглядит как `{ "phase": "intermission", "timeLeft": 6.0, "winnerId": 3, "scores": [{ "id": 3, "score": 10 }] }`. `winnerId` = 0 означает ничью или раунд без фрагов.

## Архитектура

```
cmd/server        точка входа: флаги, HTTP, graceful shutdown
internal/game     чистая симуляция: World.Update(dt, inputs), World.Snapshot()
internal/net      JSON-протокол и обёртка над WebSocket-соединением
internal/room     комната: связывает game и net, тикает мир, рассылает снапшоты
```

Зависимости направлены строго `room → game` и `room → net`, а `game` и `net` друг о друге не знают.

- **`game`** — симуляция без I/O и горутин. Вся случайность идёт из генератора с сидом, поэтому прогон воспроизводим. `Update` не аллоцирует память (`0 allocs/op` в бенчмарке).
- **`net`** — в сокет пишет только `WritePump`, остальной код ставит сообщения в очередь неблокирующим `TrySend`.
- **`room`** — одна горутина владеет миром и клиентами и общается с внешним миром только через каналы, поэтому мьютексов нет. Снапшот маршалится один раз на всех, а клиента, у которого переполнена очередь отправки, сервер отключает, чтобы медленные клиенты не тормозили остальных.

Подробности и инварианты, на которые опирается код, описаны в [`CLAUDE.md`](CLAUDE.md).

## Разработка

```sh
go build ./... && go vet ./... && go test ./...      # проверка перед коммитом
go test -race ./...                                    # гонки в room/net
go test ./internal/game -run '^$' -bench BenchmarkUpdate8Players100Bullets -benchmem
```

На Windows для `-race` нужны cgo и C-компилятор (например, WinLibs MinGW-w64), а также `CGO_ENABLED=1`.
